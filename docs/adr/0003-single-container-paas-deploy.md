# ADR 0003: Single-container PaaS deployment

- **Status**: Accepted
- **Date**: 2026-08-21

## Context

The project needs to be prepared for CI/CD on a Render/Railway-class PaaS.
Such platforms build an image from a root `Dockerfile` and hand the container
a `PORT` environment variable at runtime. The app consists of a React SPA
(`web/`), a Laravel 12 API with a Filament admin panel (`backend/`), and
expects external managed Postgres and Redis.

Previously the repo only had a dev-oriented `backend/Dockerfile`
(php-fpm, no CMD, source mounted via volumes) driven by `docker-compose.yml`
and the Makefile.

## Decision

1. **One production container** built by a root multi-stage `Dockerfile`:
   - stage 1 (`node:22-alpine`) builds the SPA with `npm ci && npm run build`;
   - stage 2 (`composer:2`) installs production PHP dependencies;
   - stage 3 (`php:8.2-fpm-alpine`) runs **nginx + php-fpm under supervisord**.
2. **PORT handling**: the nginx config is a template (`listen ${PORT}`)
   substituted by the entrypoint via `envsubst`. Default is `8000`.
   This keeps the image platform-neutral.
3. **SPA is served from the same origin**: the built `dist/` is copied to
   `backend/public/spa/`. The SPA calls `/api/v1` with relative paths,
   so no CORS configuration is needed. History-mode routing falls back to
   `spa/index.html` in nginx.
4. **External infrastructure**: Postgres and Redis are managed services;
   the container only receives connection env vars. In production
   `QUEUE_CONNECTION=sync` (v1 has no notifications, FR-4), sessions and
   cache live in Redis.
5. **Migrations** run via the PaaS release phase
   (`php artisan migrate --force`), not at container start.
6. **APP_KEY** is generated by the entrypoint when not provided.
   Consequence: recreating a container without `APP_KEY` set invalidates
   encrypted cookies (Redis sessions survive). Setting `APP_KEY` via the
   PaaS environment is recommended for stability.
7. **Config/route/view caches** are warmed at container start (not build
   time) because env vars arrive at runtime.
8. **Health check**: Laravel's built-in `/up` endpoint, routed to fpm.
9. **Local development** moved to host tooling: `docker-compose.yml` now
   provides only postgres/redis/adminer plus an `app` service under the
   `prod` profile (`make prod-preview`) running the exact production image.
   The old php-fpm dev container, `backend/Dockerfile`, `nginx/` and the
   committed `backend/composer.phar` are removed.

## Consequences

- CI gains `frontend-check.yml` (lint, typecheck, vitest, Playwright e2e)
  and a Docker build smoke job; the PaaS builds the image itself on push.
- `routes/web.php` no longer serves `/` — the SPA owns the root URL.
- Image is stateless and re-deployable; all environment comes from env vars.
